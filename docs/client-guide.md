# Визуализатор Стенариум: как вносить изменения самим

Короткое рабочее руководство. Всё, что описано ниже, делается без программиста,
кроме пункта 3 — там нужен человек, умеющий запускать скрипт.

## 0. Где живёт виджет (прочитайте это первым)

Сейчас код лежит в репозитории `github.com/Andrrreyiv/stenarium-visualizer`,
а раздаётся с GitHub Pages по адресу `andrrreyiv.github.io/stenarium-visualizer`.
Страница сайта `stenarium.ru/visualizer` показывает его в рамке по этому адресу.

Это личный аккаунт подрядчика. Пока виджет раздаётся оттуда, править его
своими силами вы физически не сможете, и это же ваш риск: пропадёт аккаунт —
на странице останется пустая рамка.

Чтобы стать самостоятельными, нужен один из двух шагов:

1. **Перенести репозиторий на ваш аккаунт GitHub.** Бесплатно, занимает около
   получаса, адрес в рамке меняется на ваш. Дальше вы правите файлы прямо в
   браузере, GitHub сам пересобирает страницу за полминуты.
2. **Положить папку на ваш хостинг** рядом с сайтом. Виджет статический: ни
   базы, ни серверного кода, только файлы.

Рекомендуем первый: правка файла в браузере не требует ни программ, ни доступа
к серверу.

## 1. Ссылки на карточки товаров — то, что осталось незакрытым

Файл `src/config/catalog.json`. У каждой позиции четыре поля:

```json
{ "code": "YB-4066D", "name": "Дуб Карамель", "article": "YB-4066D", "url": "" }
```

Править нужно **только `url`**. Вписали адрес карточки — у этой текстуры
появилась кнопка «Смотреть в каталоге». Оставили пустым — кнопки нет.
Позиции независимы: можно заполнять по одной, по мере синхронизации каталога.
Трогать код при этом не нужно вообще.

⚠️ `code` и `article` не менять. Код позиции попадает в ссылку, которой
посетитель делится и которую вы могли уже разослать; смена кода их сломает.

**Если у вас единый шаблон адреса** (например `stenarium.ru/catalog/YB-4066D`) —
скажите, и мы впишем одну строку, которая соберёт все 68 ссылок сама. Тогда
руками не придётся заполнять ничего, а новые позиции подхватятся автоматически.

## 2. После ЛЮБОЙ правки поднимите токен версии

В файлах `index.html` и `src/js/main.browser.js` есть строка вида `20260806a` —
всего в девяти местах. Замените её на сегодняшнюю дату с буквой, например
`20260812a`, одинаково во всех девяти.

Без этого посетитель, который уже был на странице, получит из кеша браузера
старую версию и ваших правок не увидит.

## 3. Заменить или добавить текстуру

Исходники берутся из вашей публичной папки на Я.Диске. Имя файла —
`Название (АРТИКУЛ).png`, именно в таком виде, скобки обязательны.

Пересборка одной командой из папки проекта:

```bash
python tools/make-assets.py
```

Нужен Python с библиотеками Pillow, numpy, scipy. Скрипт сам скачает исходники,
срежет белые кромки у неоткадрированных картинок, ужмёт каждую в два размера
(900 px на стену и 240 px в меню), сделает webp и запасной jpeg и пересоберёт
`catalog.json`.

⚠️ `catalog.json` пересобирается целиком, а значит **проставленные ссылки
затрутся**. Сохраните файл перед пересборкой и верните `url` обратно.

## 4. Что менять не нужно

- `assets/scene/` — слои интерьера (фон, карта света, диван). Они не нарисованы,
  а посчитаны из рендера: маска дивана, тени, свет. Ручная правка их ломает.
- `src/config/scene.json` — границы трёх зон замерены по кадру рендера
  (карниз на 48, стык с полом на 767). Сдвиг границ уводит панели со стены.
- Замена фотографии интерьера — это не правка файла, а пересчёт всех слоёв.
  Отдельная работа, своими силами не делается.

Проверка, что ничего не сломано, из папки проекта:

```bash
node --test tests/*.test.js
```

Должно быть 14 из 14.

## 5. Метрика

В счётчике 109470426 заведены пять целей: `viz_open` (открыл визуализатор),
`viz_pick` (выбрал текстуру), `viz_reset` (сбросил), `viz_save` (скачал
картинку), `viz_to_product` (ушёл в каталог).

⚠️ `viz_to_product` не сработает ни разу, пока поле `url` пустое у всех позиций.
Это не поломка счётчика, а следствие пункта 1.
