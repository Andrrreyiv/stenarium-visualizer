# Визуализатор Стенариум: как вносить изменения

Короткое рабочее руководство. Всё, кроме пункта 4, делается без программиста.

## 1. Ссылки на карточки товаров: это за мной

Отдельно оплачивать и заново заводить задачу не нужно. Когда синхронизация
каталога у вас закончится, пришлите любой из двух вариантов:

- **шаблон адреса карточки**, например `stenarium.ru/catalog/YB-4066D`. Тогда все
  68 ссылок соберутся из артикулов сами, и новые позиции будут подхватываться
  автоматически, без ручной работы вообще;
- либо **список «артикул, адрес»** в любом виде: таблицей, письмом, файлом.

Дальше проставлю и выложу сам. Работы там около часа, держать ради неё заказ
открытым не нужно. Сроков с вас не спрашиваю: напишете, когда будет готово.

Как это устроено, если захотите править сами. Все позиции лежат в файле
`src/config/catalog.json`, у каждой четыре поля:

```json
{ "code": "YB-4066D", "name": "Дуб Карамель", "article": "YB-4066D", "url": "" }
```

Заполняется **только `url`**. Вписали адрес, и у этой текстуры появилась кнопка
«Смотреть в каталоге». Оставили пустым, кнопки нет. Позиции независимы, можно
заполнять по одной по мере готовности каталога. Код при этом не меняется.

⚠️ `code` и `article` не менять никогда. Код позиции попадает в ссылку, которой
делится посетитель и которую вы могли уже разослать; смена кода их сломает.

## 2. Где живёт виджет и что с этим делать

Код лежит в репозитории `github.com/Andrrreyiv/stenarium-visualizer`, раздаётся
с GitHub Pages, а страница `stenarium.ru/visualizer` показывает его в рамке.

Репозиторий на моём личном аккаунте. Для вас это чужая инфраструктура: своими
силами вы там ничего поправить не сможете, и это же ваш риск на будущее.
Рекомендую перенести его к вам, это бесплатно и занимает около получаса:

1. **На ваш аккаунт GitHub.** Дальше вы правите файлы прямо в браузере, страница
   пересобирается сама. Отдельных программ не нужно.
2. **Либо на ваш хостинг**, рядом с сайтом. Виджет статический: ни базы, ни
   серверного кода, только файлы.

Скажете, когда будете готовы, передам.

## 3. После ЛЮБОЙ правки поднимите токен версии

В файлах `index.html` и `src/js/main.browser.js` есть строка вида `20260806a`,
всего в девяти местах. Замените её на сегодняшнюю дату с буквой, например
`20260812a`, одинаково во всех девяти.

Без этого посетитель, который уже был на странице, получит из кеша браузера
старую версию и правок не увидит.

## 4. Заменить или добавить текстуру

Исходники берутся из вашей публичной папки на Я.Диске. Имя файла в формате
`Название (АРТИКУЛ).png`, скобки обязательны.

Пересборка одной командой из папки проекта:

```
python tools/make-assets.py
```

Нужен Python с библиотеками Pillow, numpy, scipy. Скрипт сам скачает исходники,
срежет белые кромки у неоткадрированных картинок, ужмёт каждую в два размера
(900 px на стену и 240 px в меню), сделает webp с запасным jpeg и пересоберёт
список позиций.

⚠️ `catalog.json` при этом пересобирается целиком, а значит **проставленные
ссылки затрутся**. Сохраните файл перед пересборкой и верните `url` обратно.

## 5. Что менять не нужно

- `assets/scene/` — слои интерьера: фон, карта света, диван. Они не нарисованы, а
  посчитаны из вашего рендера. Ручная правка их ломает.
- `src/config/scene.json` — границы трёх зон замерены по кадру рендера: карниз на
  48 пикселе, стык с полом на 767. Сдвиг границ уводит панели со стены.
- Замена самой фотографии интерьера это не правка файла, а пересчёт всех слоёв
  заново. Отдельная работа, своими силами не делается.

Проверка, что ничего не сломано, из папки проекта:

```
node --test tests/*.test.js
```

Должно быть 14 из 14.

## 6. Метрика

В счётчике 109470426 заведены пять целей: `viz_open` открыл визуализатор,
`viz_pick` выбрал текстуру, `viz_reset` сбросил, `viz_save` скачал картинку,
`viz_to_product` ушёл в каталог.

⚠️ Цель `viz_to_product` не сработает ни разу, пока поле `url` пустое у всех
позиций. Это не поломка счётчика, а следствие пункта 1.
